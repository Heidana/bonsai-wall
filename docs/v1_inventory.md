## 4. Look: `choose_look` (lines 325-360)

Own stream `random.Random(seed * 7919 + 17)`, consumed in this order: species (if random), leaf (if random), tone (22% light), backdrop (weighted by `HARMONY_GROUPS[...][tone]`, if not forced), scene theme (if `--bg scene` and auto), pot.
Harmony key: `LEAF_TO_HARMONY[leaf]`, except zelkova+autumn -> `warm_autumn`. Pot choice: pool = harmony pots; for pinus, juniperus and larix, 85% of the time restrict to unglazed pots (specular `None`); then drop pots whose mean luma of levels 1-3 is within 24 of the backdrop (or deck) luma; if none remain take the highest contrast.
Stand wood and soil are not part of the look: stand style is drawn in the tree stream (section 9).
Output dict: `species leaf tone bg backdrop theme pot`; `main` adds `style`.

## 5. Pots, stands, ground, roots

- Pot styles (drawn from the tree stream per style, lines 894-913): `rect`, `oval`, `drum`, `flared`, `slab` (a natural rock slab drawn in `STONE`; only for forest). Glazes: 12 in `POTS`, 5 levels, level 4 is a specular streak on glazed pots.
- Pot width comes from the crown width (`cw = 2 * Wh`) times a style-specific factor, clamped to `[54k, 240k]` and `<= 0.72 W`. It does not depend on the trunk caliper class. Pot height is a style-specific range in `k` units.
- Stand styles: `table` 50%, `scroll` 30%, `jiita` 20% (flat burl board); for slab pots 25/25/50. Stand width = pot width + 2 x pad, `stand_pad` = 10-18k.
- Soil mound with akadama granules, moss carpet (`MOSS`), optional viewing stone (68%), optional grass blades (55% of those).
- Surface roots (`bases` list of (x, base radius)): 1-3 per side per trunk, 0-1 for forest; span widened for slant, fukinagashi, hankengai (on the side opposite `long_side`) and broom.
- Re-stamp of cascading branches in front of the pot for hankengai (line 1942).

## 6. Backdrops and scenes

- Studio (`paint_studio`, 2120): 136 dithered levels interpolated along the backdrop's 4-stop ramp; vertical base gradient, radial glow centred on the measured crown (`S.xmin`, `S.xmax`, `S.crown_top`, `S.rim_top`), horizontal vignette `0.10 * ((x - W/2)/(W/2))^2`, contact shadow below the stand. Back limbs are painted into the background (line 2158).
- Scene (`paint_background`, 2010): sky gradient (5-7 stops), stars (night), disc with halo and optional cloud bands (dusk), two ridge lines, deck planks with seams, contact shadow. Uses the tree stream (stars, disc size and position, ridges, plank noise).
- Backdrops: ink, sumi, slate, umber, tokonoma, forest (dark); washi, shikkui, fog, sage (light). Themes: dusk, night, mist.
- Dust motes: `mote` colour pair per backdrop or theme.
- All backdrop colours are multiplied by `T`, a tint derived from the backdrop's brightest stop (studio) or the theme (scene); the same tint goes on every other palette (`c()`, line 747).

## 7. Foliage renderers (lines 433-710)

| `Pad.kind` | Renderer | Species | Notes |
| --- | --- | --- | --- |
| `cloud` | `render_pad` | acer | blobs inside a wobbled ellipse, ordered shading, `ramp2` mix |
| `fine` | `render_pad` | zelkova | same code, smaller blobs, 9% pixel dropout |
| `scale` | `render_scale_pad` | juniperus | horizontal sub-clouds |
| `needle` | `render_needles` | pinus | radiating tufts; 28% of near-edge needles use `tip_ramp` |
| `larch` | `render_larch` | larix | cushions plus fascicles; dithered tip colour by outer rank |
| `spray` | `render_spray` | metasequoia | flat feathered frond with `droop`, `shear` |

All six take an ellipse description (`cx cy rx ryt ryb`), `bias`, `grad`, `shear`, `droop`, ramps and tip settings, and bake two sprites (normal and "pale flip", lines 453-475) plus `bottom` (lowest pixel per column, used for canopy shade on limbs below, line 1741). They do not take a mask. They consume the shared tree RNG in call order.

Modes: `pads` (discrete pads on primary branches), `dome` (poisson-filled rounded crown), `tiers` (stacked spray tiers; only reachable for metasequoia, since `tiers` is set only when the foliage kind is `spray`).

## 8. Layout rules (lines 892-957)

All lengths scale with `k = H / 360`.

- `deck_y = 0.80 H`, `stand_bot = 0.925 H`, stand slab thickness `max(3 or 4, 3.5k or 5.5k)`, legs `max(3, 5k)` (0 for jiita), `stand_top = stand_bot - slab - legs`, `feet = max(2, 3k)` unless slab pot, `pot_bot = stand_top + 1`, `rim_top = pot_bot - feet - pot_h`.
- Soil mound height `mound` 3.8-5.8k (4.5-7.5k for slab), `soil_half = max(8, pot_w/2 - 4k)`.
- Trunk base `xb = xc + base_off`, `yb = soil_top(xb) + 2k`; tree height `Ht = min(hfrac x H, yb - 0.07 H)`.
- Horizontal placement: `xc = W x xfrac - 0.6 (base_off + (L+R)/2)` clamped so crown span stays within 4%..96% of W and the stand within the canvas.
- Crown span is first shrunk to 0.90 W if wider; `grow_scene` then re-runs the build up to 8 times, shrinking (min 0.58 per step) or sliding until both side margins are >= 2 px and the crown top is >= 2% of H. After 8 tries it returns whatever it has without a warning.
- Design space handed to the tree: `rim_top`, `pot_w`, `soil_half`, `stand_w`, `stand_top`, `xc`, `xb`, `yb`, `Ht`, canvas `W H`. For hankengai the span includes a cascade reach of 0.45 Ht.
- The bottom canvas edge is never checked (spec already notes cascade must).

## 9. Tree builder pipeline and RNG order (`build_scene`)

One `random.Random(seed)` is created per `build_scene` call (re-created on every `grow_scene` retry). It is never split; it is consumed in this order and then handed to the animator as `S.rng`:

1. style (only if not forced: **forcing `--style X` therefore changes every later draw compared with a random run that happened to pick X**), caliper class, `long_side`.
2. style parameters (hfrac, crown width, cone fractions, asymmetry, droop, foliage mode), shari/jin flags (lines 791-870).
3. layout: pot style, pot size, stand style, stand pad, `base_off` (892-933).
4. envelope and trunk system: bends, leaders, broom fan, twin, clump, forest rows (959-1170); `draw_limb` for each leader (1175).
5. jin stubs (1210).
6. foliage attractors and primary pad scaffolds by mode (1237-1495).
7. skeleton: each attractor attaches to the cheapest earlier node; draws a quadratic arch (1505-1592).
8. pipe model radii from carried pad weight (1594-1616), flute for redwood trunks (1618).
9. `Pad` objects, twig tips, per-pad leaf ramp (1632-1714).
10. pad sprite baking in list order, sway amplitude and lag (1716-1736).
11. static layer: soil, roots, moss, stone, grass, stand, pot (1749-1948).
12. bounds from sprites and layers (1950-1956).
13. background (scene: stars, disc, ridges, planks) with the same RNG (1966-1971).
14. shared palette (`S.ix`) index assignment: background, mid, pad sprites, falling-leaf colours, motes (1976-2007). Overflow beyond 255 raises `SystemExit`.
15. back in `render_frames`: gust phases, particles, motes (animation draws from the same RNG).

Consequence for the refactor: for V1 goldens to stay identical, the tree builder, the pad baker, the static-layer painter, the background painter and the animator must keep sharing one RNG object in this order. V2 uses named streams instead (spec Determinism), so the shared object is a V1-only hand-off.

## 10. Animation (lines 2166-2297)

- `N = round(fps x seconds)` (default 120). `gust(t)` is a 3-harmonic periodic function of `2 pi t / N` (seamless loop). Each pad samples it with `lag = (cx - leftmost) / span x 0.14` (travels across the crown) and moves `round(amp x wind_dir x g)` px horizontally; `dy = 1` for strong gusts on front pads with `amp > 1.15`.
- Pad amplitude `amp = max(floor, (0.65 + 1.05 * height_frac + 0.55 * min(1, |cx - xb| / 0.6 Ht)) * 0.78 if back) * 0.88 if needle/scale`, floor 0.98 (0.78 for back pads): roughly 1-2.3 art px.
- Pale flip: when `g > 0.70` the second sprite (shimmer) is pasted.
- Falling leaves: 1-2 for pinus and juniperus, 3-5 otherwise. Each picks a front pad (lower 80% of the tree if possible), drifts with `wind_dir`, lands at `surface_y` (soil, stand top, else deck floor range), rests 15-30% of the loop. Spin tables for leaf (4 poses + rest) and needle. Colours from `leaf_fall` pairs.
- Dust motes: 9-14, Lissajous drift, two colours, blink.
- Draw order: background (with back limbs) -> back pads -> static mid layer (front limbs, soil, pot, stand) -> front pads -> motes -> leaves. Front pads always draw over front limbs; there is no branch-over-foliage layer.

## 11. Output pipeline and awww handoff (lines 2303-2486)

1. Monitors: `hyprctl monitors -j` (width, height, swapped when `transform` is odd; fractional `scale` is ignored); fallback `awww query` regex; final fallback one unnamed 2560x1440 output.
2. Outputs grouped by (w, h): one tree per group, same seed. Two monitors with different resolutions get different art grids, so different trees from the same seed.
3. `pick_scale(w, h, 360)`: scale s near `h/360`, preferring an exact divisor of h within a 0.75-1.35 band of 360 rows. Art canvas `ceil(w/s) x ceil(h/s)`.
4. Animated: GIF `bonsai-<seed>-<w>x<h>.gif` (Pillow, `optimize=True`, `disposal=1`, loop forever, duration `round(1000/fps)`), plus `still-<w>x<h>.png`. Static: PNG only.
5. Theme PNG `theme-<w>x<h>.png` (first group only, unless `--theme-from none`): frame 0 upscaled nearest to the screen size and centre-cropped.
6. `--preview DIR` additionally writes `preview-<seed>-<w>x<h>.png` (art grid x s, which can be a few pixels larger than the screen).
7. Without `--preview`: requires `awww` on PATH; sleeps `--delay`; `ensure_daemon()` polls `awww query`, starts `awww-daemon` detached if needed; per group `awww img <path> --filter Nearest --resize crop --transition-type T --transition-duration D [--outputs a,b]`; deletes older `bonsai-*` files in the cache; writes `last_seed` (never read by V1); if ML4W's `ml4w-wallpaper` exists, runs `ml4w-wallpaper <theme.png> --skip-wallpaper` detached with its log in `ml4w-theme.log`.
8. Cache dir: `$XDG_CACHE_HOME/bonsai-wall` or `~/.cache/bonsai-wall`.

## 12. The seam: what the renderer consumes today

V1's "renderer" is not a separate stage: limb rasterisation, pad sprite baking, the static layer, the backdrop and the palette all happen inside `build_scene`. The animator consumes this `Scene` (all attributes read after `build_scene`/`grow_scene` return):

| Consumer | Reads |
| --- | --- |
| `render_frames` | `S.bg` (P image + palette), `S.mid` (P image + alpha), `S.pads_back`, `S.pads_front` (each: `psprites ox oy amp lag back`), `S.rng`, `S.wind_dir`, `S.leaf_fall`, `S.mote`, `S.ix`, `S.W S.H S.k S.xc S.yb S.Ht S.floor S.soil_half S.soil_top S.stand_w S.stand_top S.species` and per pad `cx cy rx ryb` |
| `main` | `S.species S.style`, `S.bg` (theme image), `look` |
| `paint_studio` / `paint_background` | `S.xmin S.xmax S.crown_top S.rim_top S.xc S.stand_w S.stand_bot S.deck_y S.back_limbs S.k` |

Tree geometry therefore enters rendering at four points: (a) `draw_limb` calls with `pts`, `radii`, a per-stroke seed, `streaks`, `rough`, `shari_frac`, into `front` or `back` buffers; (b) `Pad` objects with ellipse parameters; (c) `bases` for roots plus style/`long_side` for root span rules; (d) `wind_dir`.

### Adjusted `TreeScene` (replaces the spec's starting shape)

Differences from the spec's sketch are marked `NEW`/`CHANGED`:

```python
@dataclass(frozen=True)
class Stroke:                       # one draw_limb call
    pts: tuple[tuple[float, float], ...]
    radius: tuple[float, ...]
    depth: tuple[float, ...]        # V2 only; V1 fills 0.0
    order: int                      # 0 trunk, 1 primary, ... (V1: 0 leaders, 1 branches, 2 jin/twig)
    wood: str                       # live | jin | dead
    bark: str
    layer: str                      # NEW: "back" (painted into the backdrop) | "front"
    streaks: bool                   # NEW: draw_limb parameter
    rough: float                    # NEW: draw_limb parameter
    shari_frac: float               # NEW: V1 band-width fraction (0 none, 1.0 jin)
    shari: tuple[...]               # V2 explicit band per point; () for V1 -> draw_limb needs a second path
    seed: int                       # NEW: per-stroke jitter seed (V1 keeps its exact values)

@dataclass(frozen=True)
class Pad:                          # CHANGED: V1 pad renderers take ellipse parameters, not a mask
    kind: str                       # cloud fine scale needle larch spray
    cx: float; cy: float; rx: float; ryt: float; ryb: float
    bias: float; grad: float; shear: float; droop: float
    back: bool
    ramp: int; ramp2: int; mix: float       # indices into the look's ramp list
    tip_start: float                        # tip_ramp itself comes from look
    amp: float; lag: float
    bake_seed: int                          # seed + int(cx*7 + cy*13)
    leaves: tuple[Leaf, ...]                # V2: exposure, age, rank (V1: empty)
    mask: bytes | None                      # V2 optional; ignored until a mask renderer exists

@dataclass(frozen=True)
class TreeScene:
    strokes: tuple[Stroke, ...]             # order preserved: V1 ties are resolved by draw order
    pads: tuple[Pad, ...]                   # builder order preserved (sprites are baked in this order)
    trunk_bases: tuple[tuple[float, float], ...]   # x, radius (y derived from layout soil_top + 2k)
    root_rules: dict                        # CHANGED: style, long_side, shrink: V1 root span rules
    wind_dir: int                           # NEW
    bounds: tuple[int, int, int, int]       # CHANGED: computed after sprite baking, not by the builder
    meta: dict
    v1_rng: object | None                   # NEW, V1 only: the shared Random hand-off (section 9)
```

Scene dressing (pot, stand, soil, moss, stone, backdrop) moves out of the tree builder into `layout` + `dress` stages that take (look, layout, rng). In V1 the builder decides pot and stand sizes from the crown, so for V1 the `Layout` is an output of the V1 builder; for V2 it must be an input (see `docs/DEVIATIONS.md`, D4).
